## 1 · The suite is red, and the cause is a test that reads a customer's file

**Established by running `pnpm test:coverage`:** 1 failed, 1926 passed.

```
FAIL src/cli/__tests__/commands.test.ts > enforceQuota
     > REFUSES a sweep that would not fit, with the real page count
     expected 'within' to be 'refused'
```

The test's fixture is the **live customer file**. `digilist()` in that describe
block calls `resolveTenant(deps(), "digilist")`, which loads
`inputs/tenants/digilist.yaml`, and the assertion's own comment records the
number it read on the day it was written:

```ts
// Tenant zero's budget is 5000 MB. Already spent 4900, and 430 pages is ~430 MB.
const decision = await enforceQuota(withUsage({}, 4900), digilist(), 430);
expect(decision.state).toBe("refused");
```

`trafficMb` is now `50000`. 4900 spent plus a 430 MB sweep fits inside it, so the
refusal correctly does not fire, and a test asserting that it does correctly
fails. **Nothing is wrong with the code.** An operator raised a budget for the
hourly watch pulse — the thing that file exists to let them do — and turned CI
red from a directory nobody thinks of as source.

**The gap is the coupling, not the number.** Ten test files load the committed
input trees:

```
tenant/__tests__/registry.test.ts     server/__tests__/accept-run.test.ts
config/__tests__/schema.test.ts       server/__tests__/settings.test.ts
cli/__tests__/commands.test.ts        watch/__tests__/{store,tick,spec,live}.test.ts
__tests__/inputs.test.ts
```

Most are fine, and one is the point: the new `__tests__/inputs.test.ts` is the
*right* shape — read-only, asserting invariants over whatever the directory
holds ("every market has a mobile 390×844 and a desktop 1440×900"), so adding a
market costs no test edit. What `commands.test.ts` does instead is arithmetic
pinned to values an operator owns.

This is the defect `pruneFs` was introduced to prevent one layer over — the
testing conventions say so out loud: *"without it a test for `evidence prune`
would be pointed at the repo's real `evidence/`."* The tenant registry has no
equivalent seam in this test.

**Closing it:** give the quota tests a synthetic tenant built in the test file,
where the budget and the page count are stated next to the assertion that
depends on them. Leave the *existence* checks (`tenant list` contains
`digilist`, its evidence root resolves under the tenant id) reading the real
file — those are invariants over the tree, and they are what `inputs.test.ts`
already does correctly.

## 2 · The watch will file 326 fabricated defects a day the moment it is armed

`inputs/tenants/digilist/watch.yaml` is `enabled: false`, annotated *"Left
disarmed until Decodo + quota are ready."* This is what happens when it is not.

**Established by reading the spec against the profiles and the journey it
selects.** Five facts, each checkable on its own:

1. **The pool contains `returning-visitor`.** `journeys:` lists `landing-page`,
   `browse`, `search`, `reader`, `returning-visitor`, and `journeyPick: seeded`
   draws **one** of them per cell — so it is drawn for roughly a fifth of cells.
2. **The journey asserts a returning session as a SITE defect.**
   `inputs/journeys/returning-visitor.yaml`:
   `{ action: assert, check: text-contains, selector: "#visitor", value: returning, severity: high, category: functional }`.
   Category `functional`, severity `high` — filed against the target.
3. **It requires a profile declaring `visitorType: returning`.** The schema
   defaults to `anonymous` (`geo/profile.ts:48`), and exactly one file in the
   tree declares otherwise: `inputs/profiles/oslo-desktop-returning.yaml`.
4. **The watch cannot reach that profile.** `devices: [mobile]`, so every cell
   resolves `<market>-mobile` — all anonymous. The one returning profile is
   desktop, so even adding its market changes nothing without a device change.
5. **The engine cannot restore a session either way.** `watch-loop.ts` calls
   `matrixRun` with no `engine`, so the sweep runs `DEFAULT_ENGINE`
   (`cli/commands.ts:146`) = `agent-browser` — which the journey's own header
   says isolates cookies per session, making every run a first-time visitor.

The failure is silent by construction. `resolveVisitorState` (`run/context.ts`)
returns early for an anonymous profile with `unmet: null` — correctly, because
from its point of view nothing is wrong; nobody asked for a session. So no
warning is raised anywhere, and the journey simply fails its `#visitor`
assertion against a site that was behaving perfectly.

**The arithmetic:** 34 markets × 1 device × 2 targets = **68 cells/hour**, one
journey drawn each. A fifth of them draw `returning-visitor`:

```
68 / 5 × 24  ≈   326 runs/day that cannot pass
326 × 30     ≈ 9,792 runs/month  ≈ 9.8 GB  ≈ 20% of the allowance
```

Twenty percent of the residential budget spent manufacturing a `high`
`functional` finding against `digilist.no`, at a rate that would bury the real
ones. The evidence packages would all be internally consistent, which is the
part that makes it dangerous: nothing in a single run's output says the run was
impossible.

**This is invariant 34 arriving one level up.** That rule says an ERRORED step is
ours whatever the journey declared — decided from the *outcome*. Here the
outcome is an ordinary assertion failure; the impossibility lives in the
*pairing* of journey and profile, which no layer currently inspects.
`allowed()` in `watch-loop.ts` hands the tick the full journey list, and
`expandMatrix` validates that names exist, never that a combination can succeed.

**Closing it, cheapest first:** drop `returning-visitor` from the watch pool —
it is a two-run journey by design and belongs in a deliberate pairing, not a
random draw. Then the real fix: let a journey declare what it requires
(`visitorType: returning`, `engine: playwright`) and refuse — or record
`unmeasured` — a scenario whose profile cannot satisfy it, before anything
launches. Invariant 19's rule that a matrix must not hide a hole is the same
rule; this is a hole it cannot currently see.

## 3 · The tenant quota now claims the entire vendor allowance

**Established by arithmetic over the current spec**, using the estimate the code
itself uses (`MB_PER_PAGE_LOAD = 1`, `tenant/quota.ts`, a measured and
deliberately under-stated figure):

```
68 runs/hour × 24        = 1,632 runs/day        (runsPerDay: 1800 — 10% headroom)
1,632 × 1 MB × 30 days   = 48,960 MB             (trafficMb: 50000 — 2% headroom)
```

`docs/milestone.md` records the account allowance as 50 GB. So one tenant's
ceiling is now the whole account, and the watch alone consumes 98% of it.

Two consequences, both of which look like something else when they arrive.
Toward the end of a month, an ad-hoc `matrix run`, a `gate check` or a re-run of
a failed sweep is refused — correctly, but the refusal will read as a broken
quota rather than as a full one. And a second tenant on that sub-account cannot
be bounded by a per-tenant ceiling that one tenant already claims in full;
`usage-probe` reads the *account's* figure, so tenant two's exhaustion would
surface as tenant one being over budget.

Not a defect — the numbers are self-consistent and the comment explains them.
Recorded because 2% headroom is a decision, and it should be one somebody made
on purpose. If the hourly pulse is the intended steady state, the honest move is
either a lower cadence, fewer targets, or a quota that reserves a visible margin
for the work a human does by hand.

## 4 · CI does not run the console's tests, and its own comment says it does

**Established by following the step's command to the package it filters.**
`.github/workflows/ci.yml`:

```yaml
# The console has its own gate, on the module that makes decisions rather than on the
# ones that draw. It is a separate package with its own vitest, so it needs its own step
# — and the integration it guards (sign in, then read data) is exactly the seam that
# shipped broken while every server test passed.
- name: Console tests with coverage
  run: pnpm test:ui
```

`test:ui` is `pnpm --filter geoqa-ui test:coverage`. `geoqa-ui` is **`apps/ui`**.
The console is **`apps/console`**, package name `@geoqa/console`. The comment
describes `apps/console`; the command runs `apps/ui`.

`apps/console/src/__tests__/console.test.ts` holds 10 tests, including the ones
over `waitUntilHealthy` — the poll that stops the console reporting ready before
the API accepts connections. They are reachable only through root `pnpm test`
(`engine && console`), and **CI never calls it**: the workflow runs
`pnpm test:coverage` (engine only) and `pnpm test:ui` (UI only).
`apps/console/vitest.config.ts` also declares no `coverage` block, so the package
has no gate under any invocation.

The name collision is the whole mechanism — two packages, one of them called
"ui" and the other rendering none of it, and a script name that reads like the
step's title.

**Closing it:** a `test:console` script filtering `@geoqa/console`, its own CI
step, and the existing comment moved to sit above the step it actually
describes. Whether the console earns a coverage threshold is a separate call;
running its tests at all is not.

## 5 · The boundary lint runs on a fallback parser now, and still fires

**Established by running it, then by breaking the tree on purpose.**
`pnpm boundaries` passes — `no dependency violations found (182 modules, 682
dependencies cruised)` — and prints:

```
‼ missing-typescript-transpiler: dependency-cruiser detected a TypeScript environment,
    but not a compatible TypeScript compiler (typescript: >=2.0.0 <7.0.0). This means
    it's likely to have missed TypeScript sources and dependencies.
```

The repo is on `typescript@^7.0.2`. dependency-cruiser supports `<7.0.0` and says
support for 7 follows when its API is published.

Invariant 18 says the layer map is a tool rather than a memory, and that a rule
with a mistyped pattern is a silent no-op. A cruiser that cannot see TypeScript
is that failure arriving through an upgrade instead of a typo — so it was tested
rather than assumed. Both a **type-only** and a **value** import of
`temporal/constants.js` were injected into `run/stages.ts`, and each produced:

```
error stages-must-not-know-temporal: src/run/stages.ts → src/temporal/constants.ts
x 1 dependency violations (1 errors, 0 warnings). 182 modules, 683 dependencies cruised.
```

The tree was restored and re-verified clean. **The gate works today**, including
on the type-only edge invariant 18 explicitly claims. What is unproven is
everything the fallback parser does *not* resolve — the warning says sources may
be missed, and a missed module is a rule that cannot fire on it. 182 modules
cruised against 94 non-test source files suggests it is resolving broadly, but
that is an inference, not a proof.

**Closing it:** watch for a dependency-cruiser release supporting TypeScript 7
and take it. Until then, treat "boundaries passed" as evidence about the modules
it cruised, and keep proving new rules fire against a deliberate violation —
which the wiring checklist already requires.

## 7 · What `gaps.md` now gets wrong

The record is the entry point for anyone starting work here, and four of its
claims no longer hold. Each was checked against the tree.

- **Its own header sends readers to a closed entry.** *"One entry is red right
  now … [B-10]"* — B-10 is marked CLOSED further down the same file, and
  `e2e/playwright-run.e2e.ts` derives the filename from `traceArtifactFormat`.
  It is the first instruction a new agent follows, and it spends the opening
  move on a non-issue.
- **A-3b: "The experiment has not been run."** `inputs/experiments/EXP-007-concurrency/summary.json`
  records a run on 2026-08-13 — 1 sample, completion / verdict-agreement /
  egress-held all 100, wall-clock factor 0.92, overall verdict `unmeasured`
  because `peak-memory-per-session` produced no reading. A-3 already describes
  that run in detail, so the file contradicts itself.
- **A-3b: "`--concurrency` does not reach it."** It does.
  `experimentKnobs(args)` (`cli/samplers.ts:842`) parses `--stability-window`,
  `--stability-reads` and `--concurrency`, refuses unparseable values, and
  `cli/index.ts` spreads `...knobs.knobs` into the options handed to
  `experimentRun`. This closes the identical residue claimed by **C-1** and
  **D-1b** — the three were described as "the same three lines", and they were.
- **C-7: "One live target."** C-16, in the same document, reports what the
  journeys found on `xala.no`. The decision *and* the measuring have happened;
  what remains is the third site, which C-7 also asks for and is the only part
  still true.

Fixing these is mechanical, and the rule the repo already states applies: if you
close something listed there, remove the entry in the same change. The header's
"start here" pointer should name whatever is actually red — as of today, that is
[finding 1](#1--the-suite-is-red-and-the-cause-is-a-test-that-reads-a-customers-file).
